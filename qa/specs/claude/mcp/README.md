# mcp

What an MCP tool call made through Claude Code looks like in Dash0: whether the server it went to is
recorded, whether the tool name is readable, and whether a call that failed can be told from one that
did not.

Regenerated by `/qa-author`, not appended to, so a gap stays visible.

## The input

`qa/mcp-fixture` is a stdio MCP server written for this area. `QA_MCP=1` on `qa/tools/qa-session.sh`
builds it, registers it twice as `qa_fixture_alpha` and `qa_fixture_beta`, and passes
`--mcp-config --strict-mcp-config`. Two tools: `echo_text` succeeds, `always_fails` returns a
JSON-RPC error. Both results are pinned by `qa/mcp-fixture/main_test.go`.

A stub rather than a real server, for three reasons. The connected claude.ai connectors are
production systems, and a QA prompt that reaches Slack or Linear is not a read this harness should
make. Their availability in a headless `claude -p` session is not guaranteed. And their output is not
reproducible, so no expectation computed before the run would survive it. `--strict-mcp-config` is
what keeps them out of the session entirely.

## Shape every session in this area has

MCP tools are deferred, so the model spends a `ToolSearch` call loading a tool's schema before it can
call it. Every run here therefore has one more `execute_tool` span than it has MCP calls. That is
useful rather than noise: it puts a native tool call in the same turn, so a naming rule that mangles
every tool equally cannot pass.

## What this area cannot cover

The content of `gen_ai.tool.call.arguments`, `gen_ai.tool.call.result`, and `exception.message`. The
API returns all three redacted, so a spec here checks presence and never value. `test/e2e/` owns
those against a mock. See `## Configure` in [../../setup.md](../../../setup.md).

The wire format, for the same reason as everywhere else in this harness: the managed install cannot
be reconfigured for one session.

## One harness change these specs depend on

`qa-compare.py` used to key the hook side of its tool table on the raw `mcp__<server>__<tool>` and the
Dash0 side on the normalized `gen_ai.tool.name`. Every MCP call therefore printed two rows, both
flagged as differing, and the tool exited `1` on a healthy run. `mcp_tool_name` now applies the same
strip to the hook side. It mirrors `NormalizeMCPToolName`, so the tool table cannot itself detect a
wrong split — the split is asserted from the raw payload name in the per-span detail instead.
