# session

What a Claude Code session looks like in Dash0 once it ends: how many spans, how they are parented,
which numbers they carry, and what a consumer can find the session by.

Regenerated by `/qa-author`, not appended to, so a gap stays visible.

| Invariant | Spec | Status |
| --- | --- | --- |
| A single turn with no tool call produces exactly one `chat` span, with token counts and cost matching the transcript | [single-turn-no-tool-session](single-turn-no-tool-session.md) | draft, passing |
| Each `PostToolUse` produces one `execute_tool` span, with its own call id, duration, and parent turn | [tool-call-produces-one-span-per-post-tool-use](tool-call-produces-one-span-per-post-tool-use.md) | draft, passing |
| A sub-agent's usage is reported once, on its `invoke_agent` span, and not folded into the parent turn | [sub-agent-usage-is-counted-once](sub-agent-usage-is-counted-once.md) | draft, passing |
| A tool call inside a sub-agent produces an `execute_tool` span | [sub-agent-tool-call-produces-a-span](sub-agent-tool-call-produces-a-span.md) | draft, **known failure**, ticket not filed. Every sub-agent tool call after the spawning turn's `Stop` is dropped, which in practice is all of them |
| Thinking tokens are attributable, rather than hidden inside `gen_ai.usage.output_tokens` | — | not written; no attribute carries them today, so there is nothing to assert yet. [finding](../../findings/thinking-tokens-are-not-exported.md) |
| `gen_ai.request.model` is present on every `execute_tool` span, not only some | — | not written; observed absent on one of two tool spans in the same turn. [finding](../../findings/tool-span-model-attribute-is-inconsistent.md) |
| A failed turn or a failed tool call sets the span status and carries the error | — | not written; needs a prompt that reliably fails |
| An interactive session carries `gen_ai.conversation.name`; a headless one does not | — | not written; needs a driver that can run interactively |

## What this area cannot cover

The wire format. The managed install cannot be reconfigured for one session, so the plugin's debug
payload log cannot be turned on and no run here sees the bytes on the wire. That also means the
content of `gen_ai.tool.call.arguments` and `gen_ai.tool.call.result` is unverifiable from here: the
API returns both redacted. `test/e2e/` owns those against a mock. See `## Configure` in
[../../setup.md](../../setup.md).
