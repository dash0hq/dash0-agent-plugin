# skills

Whether a skill invocation is observable, and whether the count of them can be trusted.

Regenerated by `/qa-author`, not appended to, so a gap stays visible.

| Invariant | Spec | Status |
| --- | --- | --- |
| A skill invocation is counted whether the person or the model invoked it | [skill-invocation-is-counted-by-either-route](skill-invocation-is-counted-by-either-route.md) | draft, passing. Was a known failure: the slash-command route produced no telemetry at all |
| A skill the model chooses unprompted is attributed to the model, not to the user | — | not written; needs a prompt that does not name the skill, so the run is not repeatable by construction |
| A skill that fails, or is interrupted, is still counted | — | not written |
| A skill's duration reflects the work it did, not the dispatch | — | not written; the slash route has no wrapped execution to time at all, which is why it is reported on the turn's `chat` span |
| A built-in slash command is not counted as a skill | — | not written; `/help` fires no turn under `claude -p` and `/compact` is not drivable headlessly, so there is no live probe. Unit-tested instead |

## Why the usual oracle does not work here

Every other area compares Dash0 against the hook-to-span mapping in `record/`. That mapping cannot
see a skill invoked by slash command, because no tool hook fires, so `qa-compare.py` agrees with
whatever Dash0 reports and calls the session healthy either way. The expectation here comes from what
was typed, which is known by construction. That is still true now the route emits telemetry: the
oracle cannot confirm it, only a query for the attribute can. Related:
[[oracle-the-hook-mapping-is-blind-to-work-that-fires-no-tool-hook]].
