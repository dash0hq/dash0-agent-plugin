# copilot/turns

Whether a second turn in one Copilot session is measured as its own turn. One turn is
[../session](../session/README.md); delegation is [../subagents](../subagents/README.md).

Every spec here needs `QA_COPILOT_RESUME`, which drives a second `copilot --resume=<id>` into the
same session. Regenerated by `/qa-author`, not appended to, so a gap stays visible.

| Invariant | Spec | Status |
| --- | --- | --- |
| Each turn's `chat` span carries only that turn's tokens, and each tool span is emitted once | [resumed-turn-is-scoped-to-itself](resumed-turn-is-scoped-to-itself.md) | active, passing. Was broken until 2026-08-28: the OTel cursor lived in the session directory that `SessionEnd` deletes, so a resumed launch re-read the file from the start |

## Not written, with the reason

| Invariant | Why not |
| --- | --- |
| A third turn behaves like the second | The mechanism is one cursor and one comparison; a third turn exercises the same code path at twice the cost. Two turns is the smallest input that can distinguish "this turn" from "the session", which is the whole question |
| An interrupted turn still produces a span | `pipeline.Process` sends a `chat` span on `SessionEnd` when a trace context is open, and that path is shared with the other runtimes and covered there. Interrupting a `copilot -p` run reproducibly is the missing piece |
| A rotated OTel file is handled across a resume | Asserted today by `TestReadTurn_resumeRotatedFile` in `internal/source/copilot`. The driver shares one file across turns on purpose, because the shared file is the harder case and is what caught the defect above |

## Why this area is separate, and why it is the expensive one

One `copilot -p` invocation is one turn. So a single-turn run cannot tell "this turn's usage" from
"the session's usage" — they are the same number, and a summing error hides perfectly. Every
per-turn claim on this runtime therefore costs two model turns, which is why they live in one place
rather than being folded into [../session](../session/README.md).

**And this is where the mechanism actually is.** Copilot's hooks carry no usage at all, so nothing
about a turn boundary is in the payloads. The plugin keeps a cursor — the id of the last native span
it consumed — and everything about per-turn correctness reduces to whether that cursor is found on
the next launch. It was not, until 2026-08-28.
