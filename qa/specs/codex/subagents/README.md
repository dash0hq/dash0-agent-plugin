# codex/subagents

What a Codex session that delegates looks like in Dash0: whether the sub-agent's work is inside the
trace, whether it keeps being exported once the agent has reported done, and whose tokens are whose.
The single-agent session is [../session](../session/README.md).

**Every spec here needs `QA_CODEX_MULTI_AGENT=1`.** Without it Codex answers a delegation prompt
directly, with no `spawn_agent` call and no complaint — a run that looks healthy and tests nothing.
See
[../../../learnings/deadend-codex-does-not-delegate-without-multi-agent-mode.md](../../../learnings/deadend-codex-does-not-delegate-without-multi-agent-mode.md).

Regenerated by `/qa-author`, not appended to, so a gap stays visible.

Was broken until 2026-08-26: the anchor was keyed on an `agent_id` that 0.149.1's spawn response stopped carrying, and the sub-agent's spans hung outside the trace |
| Work an agent does after its `SubagentStop` is still exported, and a spawn made then anchors its own child | [a-reused-agent-keeps-producing-spans](a-reused-agent-keeps-producing-spans.md) | draft, passing. Was broken until 2026-08-26: a Codex `SubagentStop` ends a task rather than the agent, and consuming the agent's context there dropped 2 of 7 tool spans |

Each `invoke_agent` span covers one completed task, and splitting a reused agent's usage per task needs the `SubagentStop` partition that [../session/turn-usage-is-scoped-to-its-own-turn](../session/turn-usage-is-scoped-to-its-own-turn.md) documents. Worth writing only if a defect suggests the split is wrong; the sum is asserted today |

## Why these stay draft

Their input depends on the model choosing to delegate, and each says a run that does not is discarded
rather than failed. A gate that sometimes wants a re-run teaches people to ignore red. The four in
[../session](../session/README.md) are active because the driver forces their input.

## The prompts that reach this surface

```sh
# one sub-agent, one task
QA_CODEX_MULTI_AGENT=1 qa/tools/qa-session-codex.sh \
  'Spawn a sub-agent to run the shell command "echo from-the-subagent". Wait for it to finish, then reply with exactly the word delegated.' <id>

# reuse: the same agent works again after its first SubagentStop
QA_CODEX_MULTI_AGENT=1 qa/tools/qa-session-codex.sh \
  'Spawn a sub-agent named worker that runs the shell command "echo alpha". Wait for it to finish. Then send that SAME agent a follow-up task to run the shell command "echo beta", and wait for that too. Then reply with exactly the word delegated.' <id>

# nesting: the model puts the second spawn inside the first, which is also reuse
QA_CODEX_MULTI_AGENT=1 qa/tools/qa-session-codex.sh \
  'Spawn two sub-agents, both with the task name run_echo: the first runs the shell command "echo alpha", the second runs "echo beta". Wait for both, then reply with exactly the word delegated.' <id>
```

## What this area cannot cover

**Whether a parent is the *right* one.** `qa-compare.py` catches a parent that no span carries, which
is what both defects above broke. A tool span moved from its turn to another turn would still pass,
so every spec here asserts the tree by querying the spans.

**Claude's sub-agents.** They stop once, and a call arriving after that is stale and correctly
dropped — the opposite of the invariant here, and the one place where the two runtimes' correct
behaviour genuinely differs. See
[../../../learnings/hooks-a-codex-subagent-is-reusable-a-claude-one-is-not.md](../../../learnings/hooks-a-codex-subagent-is-reusable-a-claude-one-is-not.md).
