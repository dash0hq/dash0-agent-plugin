# codex/session

What one OpenAI Codex session looks like in Dash0 once it ends: the numbers on its spans, and the
attribute surface they carry. Sub-agents are [../subagents](../subagents/README.md).

Every spec here needs no flag beyond the driver's defaults. Regenerated by `/qa-author`, not appended
to, so a gap stays visible.

| Invariant | Spec | Status |

Was broken until 2026-08-25: `user_message` is the boundary the reader keyed on and codex-cli 0.149.1 never writes it, so turn 2 reported 58594 input tokens for a turn of 29445 |

## Not written, with the reason

| Invariant | Why not |
| --- | --- |
| An MCP call names its server and the span carries the stripped tool name | Asserted today by the golden test in `internal/source/codex` against a real captured `mcp__everything__echo` pair. A live spec would add drift detection only, and needs MCP fixture support the Codex driver does not have: Codex takes servers from `[mcp_servers.*]` in `config.toml`, not from `--mcp-config` |
| A failed tool call sets the span status | Nothing in the Codex harness fails on demand. The Claude arm uses `qa/mcp-fixture`'s `always_fails`, unreachable until the driver can register an MCP server |
| A skill invocation is attributed on the span | **Not applicable.** Codex 0.149.1 has no skill concept: `codex plugin` manages plugins, and no captured session has ever carried a `Skill` tool. The shared extractor would fire if Codex added one, which makes it a unit-test question until then |
| A compressed rollout is marked rather than silently dropped | No `.zst` rollout has ever been observed, so the input does not exist. `dash0.codex.rollout.compressed` is the marker to look for on the day one appears. Belongs in a unit test against a forged rollout |
| Hook trust is reproduced so Codex runs the hooks without a prompt | `codex-recorder-is-trusted-and-the-plugin-keeps-its-index` in [../../../setup.md](../../../setup.md) checks it before every run, and `test/e2e`'s no-bypass canary catches serialization drift in CI. Both are cheaper than a spec and one runs without auth |
| No span has a parent that no other span carries | Now a check inside `qa-compare.py`, running on every comparison in both runtimes. A spec would assert what the tool already asserts everywhere |

## The turn boundary, and why the reader disagrees with the product

`qa-rollout.py` counts `user_message` and codex-cli 0.149.1 writes `task_started`. That divergence is
deliberate: the independent reader must not learn the product's rule, or the comparison becomes a
restatement of it. A spec needing a per-turn figure partitions the rollout's `token_count` events by
the recorder's `Stop` timestamps instead, which a different process writes without reading a rollout
at all.
